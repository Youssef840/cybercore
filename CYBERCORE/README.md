# CYBERCORE 2.0.0

فيرموير عربي للوحة **CYD-2USB / ESP32-2432S028R** بشاشة ILI9341 ولمس XPT2046. الثيم الافتراضي أخضر غامق وأسود. أدوات الشبكات دفاعية؛ المسح اللاسلكي يستقبل الإعلانات سلبياً. الاتصال بالشبكة وping وفحص LAN والبورتات أدوات تشخيص ترسل حركة عند اختيارها صراحة.

## البناء والرفع

على ويندوز ضع المشروع في مسار قصير (مثل `C:\dev\CYBERCORE`). من مجلد `CYBERCORE`:

```powershell
python -m pip install platformio pyserial pillow
python -m platformio run -e cyd2usb
python -m platformio run -e cyd2usb -t upload --upload-port COM4
python tools/hardware_smoke.py COM4
```

استبدل `COM4` بمنفذ اللوحة على جهازك. لا تحذف `scripts/fix_spi_symbol.py`: يحل تعارض الرمز `spi` بين مكتبتي TFT_eSPI وSmartRC-CC1101 أثناء البناء.
قبل أول رفع يُنصح بأخذ نسخة احتياطية من الفلاش الأصلي: `python -m esptool --port COM4 read_flash 0 0x400000 backup/original_firmware_4MB.bin`.

## التحكم دون الاعتماد على دقة اللمس

- شريط دائم: **أعلى / أسفل / اختيار / السابق / التالي / رجوع**.
- السابق والتالي ينقلان التحديد بين العناصر. أعلى وأسفل يختاران أقرب عنصر في الاتجاه العمودي.
- زر **BOOT**: ضغطة قصيرة = التالي؛ إمساك 550–1799 ms ثم الإفلات = اختيار؛ إمساك 1800 ms أو أكثر ثم الإفلات = رجوع.
- القوائم الكبيرة مقسمة إلى صفحات. أزرار الصفحات جزء من العناصر القابلة للتحديد.
- لوحة المفاتيح وصفوف اختيار شبكة Wi-Fi أو جهاز BLE قابلة للتحكم بالتحديد أيضاً.
- لعبة الأفعى: أعلى/أسفل للاتجاه العمودي، السابق/التالي لليسار/اليمين، اختيار للإيقاف المؤقت أو الاستئناف أو إعادة اللعبة بعد الخسارة.
- في لوحات DevKit العامة تُقرأ أزرار UP/DOWN/OK المحددة في `config.h`؛ لا تُفترض أزرار إضافية على CYD.

## معايرة الشاشة

في **الإعدادات → ترتيب الألوان**، كل اختيار ينتقل إلى وضع من ثمانية: RGB/BGR × عكس البايتات × عكس العرض. شاهد مربعات **R G B W K** واختر الوضع الذي يعطي الأحمر والأخضر والأزرق والأبيض والأسود الصحيح؛ بعدها اضغط حفظ أو ارجع. وضع اللون محفوظ في NVS. لا تعتمد على صور framebuffer لتحديد اللون الفعلي.

في **الإعدادات → معايرة اللمس**، اضغط العلامات الثلاث بالقلم وارفعه بين كل علامة. تجمع المعايرة 15 عينة لكل نقطة وتستنتج تبديل المحورين واتجاههما. القيم محفوظة في NVS. تغير التعامل مع اللمس ليتحمل انقطاع ضغط قصيراً بدلاً من توليد نقرات زائفة فوراً.

## الأدوات

- Wi-Fi: ماسح، تدقيق التشفير، محلل القنوات، عداد إطارات الفصل، مقارنة الأسماء المكررة، عداد الحركة، اتصال وأدوات شبكة.
- **الشبكات المخفية:** مسح سلبي لإعلانات SSID الفارغة، مع BSSID والقناة وRSSI. لا يكشف اسم الشبكة المخفي بالضرورة.
- BLE: ماسح ورادار ومراقب جهاز محدد. اختر صف الجهاز من الماسح لبدء تتبعه، أو افتح المراقب ثم اختر جهازاً. يعرض RSSI وأقل/أعلى قيمة وعدد دورات الرصد وآخر ظهور؛ لا يتصل بالجهاز. العناوين العشوائية قد تتغير، وRSSI ليس مقياس مسافة موثوقاً.
- المعمل: ماسح I2C وقياس ADC وكشاف.
- أدوات: QR ومؤقت وأفعى و**مدير SD** و**ساعة ومنبه**.

## خيارات المسح والرصد

من الإعدادات أو قسم الأدوات افتح **خيارات الأدوات**. الخيارات مشتركة بين الأدوات ذات العلاقة وتحفظ في NVS:

| الخيار | التأثير |
|---|---|
| مدة قناة Wi-Fi | 100–1000 ms لكل قناة، وليست مدة المسح الكامل |
| القناة | صفر = جميع القنوات / تنقل، أو 1–13 للتثبيت |
| أقل إشارة | فلترة RSSI من -110 إلى -30 dBm؛ ليست حساسية عتادية للراديو |
| مدة BLE | 1–10 ثوان للدورة |
| تحديث تلقائي وفترته | إعادة مسح Wi-Fi/BLE بعد اكتمال الدورة |
| حفظ تلقائي SD | حفظ نتائج Wi-Fi/BLE وسجل مراقب BLE ولقطات عدادات الرصد |
| عتبة إطارات الفصل | عدد إطارات في نافذة نصف ثانية لإظهار تحذير |

مسح Wi-Fi وBLE غير متزامن حتى يظل التنقل متاحاً أثناء المسح. الرادار ومراقب BLE يرصدان دورياً بطبيعتهما. لكاشف الفصل ومحلل الحركة أزرار تصفير، تبديل قناة، إيقاف/تشغيل وحفظ لقطة SD. تصنيف التشفير والأسماء المكررة وارتفاع إطارات الفصل **مؤشرات للمراجعة** ولا تثبت وحدها وجود هجوم أو أمان الشبكة.

## بطاقة SD

VSPI: SCK=18, MISO=19, MOSI=23, CS=5. شاشة TFT على HSPI واللمس bit-bang بأطراف منفصلة. دعم SD الحالي مخصص للبطاقة المدمجة؛ CC1101 غير مستخدم أثناء ذلك.

- مدير الملفات يعرض حتى 64 عنصراً في المجلد، مع صفحات وفتح مجلد والرجوع للأب وتحديث.
- يعاين الملفات كنص ASCII على صفحات؛ الملفات الثنائية تعرض معاينة محدودة، وليست مشغل وسائط.
- حذف ملف يتطلب **تأكيداً منفصلاً**. لا حذف للمجلدات ولا حذف تلقائي.
- تحفظ النتائج CSV تحت `/CYBERCORE/`: `wifi.csv`, `audit.csv`, `twins.csv`, `hidden.csv`, `ble.csv`, `ble_track.csv`, `deauth.csv`, `traffic.csv`.
- الوقت في ملفات الرصد هو `uptime_ms` منذ الإقلاع. لا تسجل كلمات مرور الشبكات. أسماء الأجهزة والشبكات تقتبس كحقول CSV مع معالجة بادئات صيغ الجداول.
- يلزم اختبار القراءة والكتابة ببطاقة فعلية؛ فتح شاشة المدير لا يثبت توفر بطاقة أو نجاح التخزين.

## الساعة والمنبه

المنطقة الحالية UTC+3. يمكن زيادة الساعة/الدقيقة يدوياً أو طلب NTP بعد الاتصال بـWi-Fi. تعمل مراقبة المنبه من الحلقة الرئيسية حتى عند فتح أداة أخرى؛ التنبيه **مرئي بالشاشة وLED أخضر** لمدة تصل إلى دقيقة، ويسكت عند الضغط. لا توجد صفارة مفترضة. إعداد موعد المنبه محفوظ، لكن الوقت نفسه يحتاج ضبطاً أو مزامنة بعد فصل الطاقة؛ لا توجد RTC خارجية مضافة. العمليات الحاجبة مثل نقل لقطة الشاشة أو ping قد تؤخر عرض المنبه.

## Serial والتطوير

115200 baud. الأوامر حساسة لحالة الأحرف:

| الأمر | الوظيفة |
|---|---|
| `U D N P E B` | أعلى، أسفل، التالي، السابق، اختيار، رجوع |
| `V` | الحالة: الإصدار ومدة التشغيل والذاكرة ووضع اللون والمعايرة والشاشة |
| `X` | تشغيل/إيقاف طباعة قراءات اللمس الخام |
| `C` | تدوير وضع الألوان وحفظه وإعادة رسم الشاشة الحالية |
| `S` / `T` | نقل framebuffer / أعمدة ألوان خام للتشخيص |
| `1`–`9`, `a`–`h` | اختصارات الأدوات الأصلية |
| `i j k l m` | SD، شبكات مخفية، مراقب BLE، ساعة، خيارات الأدوات |
| `0` | رجوع |

```powershell
python tools/capture_screen.py COM4 capture.png
```

التصوير لا يعيد تشغيل اللوحة بمجرد فتح المنفذ؛ أضف `--reset` عند الحاجة. الصور للتحقق من التخطيط فقط. اختبار `hardware_smoke.py` يحتاج ترك اللوحة دون لمس أثناء تشغيله، ويفحص الاستجابة والتنقل وتكرار تهيئة BLE وفتح الأدوات، ولا يحذف ملفات أو يتصل بشبكة.

## المعمارية الحالية

`main.cpp` → `core/App` (مكدس التنقل ودورة حياة الشاشات)؛ `Input/Touch` للإدخال والمعايرة؛ `Settings` للتخزين NVS؛ `BleReceiver` للمسح السلبي غير المتزامن؛ `Storage` للبطاقة وCSV؛ `ui` للرسم والخط العربي والتحديد؛ `screens` للأدوات؛ `MainMenu.cpp` يسجل القوائم.

بيئة الإنتاج المختبرة هي `cyd2usb`. تبقى `cyd2usb_fonttest` لاختبار الخط، و`ili9341/st7789` ملفات تعريف للوحات عامة تحتاج تحقق عتادي مستقل. لا توجد أدوات RF لـCC1101 مضافة في هذه النسخة؛ الأطراف والمكتبة موجودة للتوسعة فقط.


## إضافات 1.3.0

شاشة معايرة اللمس تعزل النقرات المترجمة عن التنقل العام حتى لا تؤدي الإحداثيات القديمة إلى الخروج منها أثناء الضبط.

- **PMF / WPS:** يستقبل Beacon وProbe Response فقط، ويفحص RSN لعرض PMF required/capable/not set/unknown، ويرصد إعلان WPS. يعرض حتى 32 نقطة وصول مع قناة وإشارة وBSSID في التفاصيل، وإيقاف/استئناف وحفظ `beacon_audit.csv`. إعلان WPS لا يثبت قابلية الاستغلال، وخصائص الإعلان لا تثبت حالة اتصال عميل. يتعامل مع أطوال الحقول غير الموثوقة ويرفض الإعلانات المبتورة.
- **فاحص الخدمات:** أدخل IPv4 لجهاز داخل الشبكة المتصلة، ثم ابدأ فحص 16 خدمة TCP شائعة. المهلة قابلة للاختيار 100/250/500/1000 ms، والفحص قابل للإيقاف. يستبعد عنوان اللوحة وعناوين الشبكة والبث؛ `NO REPLY` قد يعني فلترة أو مهلة ولا يثبت إغلاق البورت. يحفظ `services.csv`. لا يفحص جهازاً بمجرد فتح الأداة.
- **تشخيص DNS:** عدّل اسم النطاق ثم اختبره عبر DNS الشبكة المتصلة. يرسل استعلام A واحداً وينتظر حتى 3 ثوان دون تعطيل التنقل؛ يعرض IPv4 والزمن أو NXDOMAIN/مهلة/خطأ. يتحقق من مصدر الرد ومعرفه والسؤال وحدود السجلات. رد UDP المختصر لا يتحول تلقائياً إلى TCP، وهذه ليست أداة للتحقق من DNSSEC. يحفظ `dns.csv` عند وجود إجابة IPv4.
- اختصارات Serial: `n` لتدقيق الإعلانات، `o` للخدمات، `p` لـDNS، و`J` لتشغيل الاختبارات المدمجة لمحلل RSN/DNS (النجاح: `failures=0`).

مراجع التنفيذ: [بتات PMF في hostap](https://w1.fi/wpa_supplicant/devel/wpa__common_8h.html)، [رسائل DNS في RFC 1035](https://www.rfc-editor.org/rfc/rfc1035.html). لا توجد هجمات فصل أو تخمين كلمات مرور أو استغلال أو spam ضمن هذه الإضافات.


## إضافات 1.4.0

- **مراقب تغيّر الشبكات:** دورات مسح Wi-Fi سلبية، تقارن حتى 32 نتيجة حسب BSSID وتسجل الظهور وعدم الرصد وتغير الاسم والتشفير والقناة وتغير RSSI بمقدار 20 dB أو أكثر. سجل دائري لآخر 32 حدثاً، مع توقيف/استئناف وصفحات وتصدير `wifi_watch.csv` وحفظ تلقائي حسب خيار SD. الضغط على شريط المرجع ينشئ مرجعاً جديداً ويمسح سجل الذاكرة فقط. يحتفظ بالمرجع في RAM أثناء التنقل، لا بعد فصل الطاقة. عدم الرصد ليس دليلاً على اختفاء فعلي: المسح وفلترة الإشارة وحد 32 نتيجة قد تؤثر عليه. يستخدم فترة التحديث المشتركة حتى مع تعطيل التحديث التلقائي لباقي الماسحات، لأنه أداة مراقبة مستمرة بطبيعته.
- **محلل إعلانات BLE:** استقبال سلبي حتى 16 جهازاً، مع تفاصيل عنوان ونوع عنوان رقمي وRSSI وTX power عند الإعلان عنه، وأول UUID وعدد UUIDs، وCompany ID رقمي وبادئة بيانات الشركة (16 بايت) وبادئة الحمولة (24 بايت). لا يتصل بخدمات GATT ولا يعرّف الشركة من رقمها دون قاعدة بيانات. ثلاث صفحات للتفاصيل؛ تبقى اللقطة ثابتة أثناء عرض التفاصيل. يحفظ `ble_ads.csv`؛ البيانات المصدرة بادئات مختصرة وليست نسخة كاملة من كل إعلان.
- **فاحص رؤوس HTTP:** هدف IPv4 داخل الشبكة المتصلة، ومنافذ 80/8080/8000/8888. يرسل HEAD واحداً للمسار `/`، ويقرأ حتى 8 KiB و64 سطراً (255 بايت للسطر) بمهلة إجمالية 3 ثوان بعد الاتصال. يعرض حالة HTTP ووجود CSP/XFO/XCTO/Referrer-Policy/HSTS، وServer وLocation. لا يتبع التحويلات، ولا يجلب جسم الصفحة، ولا يفحص TLS أو DNS أو صلاحية سياسات الرؤوس. `SEEN` يعني وجود قيمة غير فارغة، ولا يعني أن السياسة آمنة. HSTS المرصود على HTTP لا يفعّل حماية المتصفح. بعض الأجهزة لا تدعم HEAD؛ لا يعيد المحاولة بـGET تلقائياً. يحفظ النتائج المكتملة فقط في `http_headers.csv`.
- **QR قابل للتحرير:** إدخال حتى 63 بايت بلوحة المفاتيح، مع هامش أبيض بأربع وحدات حول الرمز. النص يبقى في RAM خلال الجلسة، ولا يحفظ تلقائياً في NVS. حفظ SD اليدوي يصدر النص إلى `qr_text.csv`، وليس صورة الرمز.
- اختصارات Serial الجديدة: `r` مراقب Wi-Fi، و`s` محلل BLE، و`t` فاحص HTTP. اختبارات `J` تشمل HTTP أيضاً.

مرجع طريقة HEAD: [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html). مرجع تفسير الرؤوس وحدود HSTS على HTTP: [OWASP Secure Headers](https://secure-headers-project.owasp.org/response-headers/).

### الشبكة والحدود

- الأدوات الشبكية تبدأ باختيار المستخدم. باستثناء المسح السلبي، يلزم الاتصال من «اتصال وأدوات» أولاً. `gateway` يعني بوابة الشبكة، و`auto` خادم DNS الأول، و`auto2` الثاني؛ يمكن استبدالها بعنوان IPv4.
- TCP وHTTP وتعريف الخدمة محصورة بمضيف داخل الشبكة المتصلة، وتستبعد عنوان اللوحة والشبكة والبث. مهلة اتصال TCP 250 ms. فشل الاتصال لا يثبت إغلاق المنفذ.
- DNS: UDP فقط، 3 ثوان لكل استعلام، حتى 512 بايت و8 سجلات معروضة من قسم الإجابات، وكل سجل حتى 127 محرفاً. لا تتبع CNAME باستعلام جديد ولا تتحقق من DNSSEC ولا تعيد المحاولة بـTCP عند TC. تقارن ردود الخادم ومعرف الاستعلام والسؤال، وتتحقق من الأطوال ومؤشرات ضغط الأسماء. نتائج مقارنة المحللين قد تختلف بسبب CDN أو التخزين المؤقت أو حدود العينة.
- NTP: UDP فقط، 3 ثوان، مع التحقق من المصدر ونسخة/نمط الرد وstratum وLI وطابع originate. غير موثق تشفيرياً؛ نتيجة تشخيص لا مصدر وقت موثوقاً أمنياً. الانحراف يعتمد صحة ساعة اللوحة؛ معالجة era تستخدم نطاق الوقت الحديث.
- اقتراح القناة تقدير من إعلانات APs وفلترة RSSI، وليس قياس إشغال طيف أو ضماناً لأفضل أداء. يستخدم جميع القنوات بدلاً من تثبيت قناة المسح المشترك.
- تنفذ المهام المنتظرة داخل update دون انتظار رد الشبكة في حلقة حاجبة. الاتصال TCP نفسه محدود بـ250 ms. تحديث وقت الدورة بعد معالجة الإدخال يمنع انتهاء مهلة بدأت للتو أثناء رسم الشاشة.
- تصدير يدوي إلى `/CYBERCORE/advanced_lab.csv`، يتضمن معرف دفعة وزمنها ومعرف الأداة والمدخلات الثلاثة ورقم سطر النتيجة. لا حفظ تلقائي لمدخلات المختبر أو كلمات المرور. صورة QR والنصوص السابقة لا تتغير بإضافة المختبر.

### تطوير واختبار

`L` يفتح المختبر. `!00` إلى `!25` تفتح وظيفة بعينها. `J` يطبع اختبارات المحلل الأصلي ثم `[lab-test] failures=0` عند النجاح. الاختبارات الداخلية تشمل DNS A/AAAA/MX/TXT/NS/PTR وضغط الأسماء والحزم المبتورة وNTP وحسابات CIDR والتحويلات وSHA-256 ومتغيرات IPv6 وMAC.

```powershell
python tools/advanced_smoke.py COM4
```

الاختبار يفتح الصفحات الـ26 ويشغّل الحسابات والتحويلات ويكمل مسح قناة سلبياً، ويتحقق من الذاكرة ومدة التشغيل والمعايرة. لا يفحص خادماً حياً ولا يكتب ملفات SD. يحتاج ترك اللوحة دون لمس أثناء تشغيله.
